# AI 使用、个人贡献和验证声明

## 已发生的协作

用户提供完整校招考核要求，并授权 AI 从四题中选择一题实现。本项目由 Codex 会话选择第 3 题并辅助生成。

| 工作 | 本次实际承担者 |
|---|---|
| 题目材料与交付目标 | 用户提供 |
| 选题、需求拆解、模块设计 | Codex 辅助完成 |
| Python 代码、合成数据、测试、文档、打包 | Codex 辅助生成并执行 |
| 本地测试、错误修正、结果核对 | Codex 通过本机命令实际执行 |
| 交互模型动作选择 | 当前 Codex 会话逐步读工具结果后选择 |
| 候选人个人实现/修改 | 当前会话没有可核实记录，不代填 |
| 候选人亲自复跑、理解确认、面试讲解 | 待候选人完成并据实补充 |

不将 AI 输出改称候选人独立完成，也不编造个人学习经历。候选人提交前应修改此表，写清自己实际改动、执行过的命令、观察到的结果和不能解释的部分；没有改动也应如实说明。

## 工具使用范围

使用 Codex 编程与终端工具生成和运行项目；使用 OpenAI Docs 技能和官方文档核对 Responses 工具调用；用户创建了公开 GitHub 仓库并授权上传；Codex 使用 GitHub 连接工具提交本项目代码及验证材料，并核对远端内容。未读取无关业务仓库内容。没有使用其他候选人答案。没有启用多 Agent 或委派其他 AI 编写模块。

代码采用标准库，无第三方 Agent 框架。语料均为本项目合成数据；不包含用户密钥、真实制度或个人隐私。Git 提交身份采用明确的通用辅助提交身份，不冒用候选人身份。

## 模型使用的三类边界

1. `offline_mock`：规则策略，只验证流程，不是真实模型。
2. `stdio_bridge:codex-assistant-interactive`：本次 Codex 会话在运行中的 CLI 返回观察后逐条输入动作。没有在开始运行时提交整段预制动作脚本；Trace 由程序保存。精确服务端模型 ID、token 用量和模型签名不可从这个桥获取，未编造这些字段。
3. `responses_api:<model>`：已实现原生函数调用适配，但本环境没有 OPENAI_API_KEY/OPENAI_MODEL，端到端自动 API 运行未完成。模拟 transport 的合同测试不能代替真实调用。

## 已执行验证

自动测试和场景输出见 `examples/mock/`；交互记录见 `examples/live/`；完整重放核验见 `examples/trace-verification.json`。实际结果保留错误和未完成状态，不手工改成成功。公开记录只包含动作参数、简短理由、工具输出与状态，不提交模型内部思维过程。

候选人提交前建议亲自完成一次正常运行、一次冲突运行、一次修改数据后的运行，解释为何不能凭版本新旧解决冲突，并在这里记录实际命令与发现。此建议是后续个人验证事项，不把尚未做的工作写成已完成。
